# 独立部署迁移方案与执行计划

目标：保留现有 PRD、V2 台账与完整协作数据，将运行环境迁到普通 Linux 服务器，不依赖 GPT Sites、D1、海外字体或 CDN。

架构：复用 React 页面，改用 Next.js Node.js 运行时和 Node 24 内置 SQLite。数据库文件放在持久卷，单实例部署。SQLite 适配器保留现有参数化 SQL 和原子 batch 事务，原稿与 V2 的键空间保持隔离。口令及新会话密钥从环境变量注入。

数据：随代码提供受控快照 seed/reviews.json、原稿 lib/document.json、V2 正文和意见台账 lib/releases/v2.json。只在空库启动时事务导入；后续启动不覆盖用户写入。失败导入整体回滚，拒绝向已有非托管库导入。访问尝试和旧会话密钥不迁移。

执行与验收：

1. 新建独立目录，分页导出五张业务表；核对内容与数量。
2. 先验证导入和事务失败用例，再实现 SQLite 适配、幂等初始化和一致性备份。
3. 移除 Cloudflare/Sites 运行入口；接入 Node 环境配置、反向代理来源校验和健康检查。
4. 使用 Next.js standalone 构建，提供 Docker Compose、原生 Node 运行、Nginx、备份恢复和离线迁移说明。
5. 用真实快照验证导入逐行一致、重启不覆盖、事务回滚；运行原版与 V2 HTTP 回归及恢复后的数据检查。构建后检查静态资源不泄漏正文与密钥。
6. 打包源码及数据、生成校验和。没有目标服务器凭据时，交付部署库，不宣称已在国内服务器上线。当前环境无 Docker 时明确 Docker 验证边界。

本次不升级为多副本数据库、不改变产品需求、不自动同步两个站点的新写入，也不发布到现有 Sites。
